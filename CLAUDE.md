# BadLink — заметки для Claude

Эмулятор плохого канала для Windows: WinDivert перехватывает весь IP-трафик выбранного интерфейса,
движок ограничивает скорость (база ± разброс, смена ~раз в секунду) и устраивает прерывания (обрыв/замирание).
GUI на tkinter, без сторонних runtime-зависимостей. Пользователь запускает собранный `BadLink.exe`, не `main.py`.
Язык интерфейса, README, комментариев и коммитов — русский.

## Команды

```bash
python -m unittest discover -s tests -v
```

```bash
python main.py --selftest
```

```bash
powershell -ExecutionPolicy Bypass -File build.ps1
```

Линтер в CI: `ruff check .` (ruff 0.16.9, настройки в `pyproject.toml`, длина строки 120).

## Устройство

- `netem/engine.py` — вся логика канала; один поток `_tx` принимает решения, `_rx` только кладёт пакеты в inbox.
  Отдельные `random.Random` на скорость приёма/отдачи и на прерывания — seed воспроизводит прогон независимо от трафика.
  Движок не знает про WinDivert: IO-объект с `recv/send/shutdown/close` (в тестах — `FakeIO`).
- `netem/windivert.py` — ctypes-обёртка WinDivert 2.2 и `segment_tcp`: нарезка LSO/RSC-суперпакетов до MTU.
  Без нарезки на 1–2 Мбит/с график идёт рывками — не убирать.
- `netem/iperf.py` — iperf3 как дочерний процесс в Job Object (KILL_ON_JOB_CLOSE), чтобы не оставалось сирот.
- `netem/gui.py` — окно; фоновые потоки общаются с GUI только через `self._ui_queue`, опрос в `_fast_tick`.
- Версия — `netem/__init__.py`; тег релиза `vX.Y.Z` обязан ей совпадать (проверяется в CI).

## Правила

- **Никогда не запускать эмуляцию на основном интерфейсе машины разработки** — это рвёт собственную сеть.
  Для реальных тестов — отдельный профиль `--settings <файл>` с безопасным интерфейсом (например, `vEthernet (WSL)`
  и iperf3 внутри WSL). `--start` запускается только на интерфейсе, явно сохранённом в профиле.
- Не трогать `settings.json` пользователя.
- Закрывать свои процессы только по PID, не по имени.
- Windows PowerShell 5.1: `Set-Content -Encoding utf8` пишет BOM — для файлов проекта использовать
  `[IO.File]::WriteAllText(..., New-Object Text.UTF8Encoding($false))`. Исключение — `build.ps1`: ему BOM нужен,
  иначе PS 5.1 ломает кириллицу.
- Кириллица в сообщении коммита: писать сообщение в файл UTF-8 и `git commit -F <файл>` (pipe в PS 5.1 портит текст).
- Консоль CI-раннера в cp1252: любой вывод с кириллицей в stdout — через `sys.stdout.reconfigure(encoding="utf-8")`.
- Windows-iperf3 с блоком по умолчанию (128K) на низких скоростях показывает ложные ступеньки 1,05/2,1/0 Мбит/с —
  в тестах всегда `-l 8K`.
